# Healthcare Lab v1.1.0

Healthcare Lab v1.1.0 introduces a persisted, typed Settings workspace and
zero-edit Docker startup for configuring and operating the interoperability lab.

## Highlights

- Added automatic provisioning and identity recovery for managed OIE channels.
- Added persisted typed configuration with explicit ownership and migration
  behavior.
- Added a modular Settings workspace with guided setup and readiness reporting.
- Added persisted Medplum connection and OAuth configuration, diagnostics, and
  retry-safe workflow behavior.
- Added configurable GDT bridge profiles, filesystem diagnostics, and runtime
  reload behavior.
- Added persisted dcm4chee connection profiles, DICOM diagnostics, TLS controls,
  and readiness reporting.
- Added external AP device profiles for HL7, GDT, and DICOM integrations.
- Added zero-edit Docker Compose startup and dashboard guidance for incomplete
  integration setup.

## Fixed

- Restored credential-free fresh installation without requiring a repository
  `.env` file or optional integration secrets.
- Aligned default dcm4chee TLS settings so fresh typed-configuration bootstrap
  is valid.
- Prevented optional secret values from appearing in Compose rendering,
  application projections, command output, or generated diagnostics.
- Improved cross-platform deployment-wrapper isolation and release readiness
  verification.

## Upgrade notes

- Existing persisted Settings remain authoritative and are not overwritten by
  later environment changes.
- Existing deployments may retain eligible legacy configuration values during
  the first startup migration.
- Deployment-owned secret-file paths remain configurable through `.env`;
  application secret values remain owned by persisted Settings.
- Review dcm4chee TLS settings after upgrade if the deployment previously used
  custom TLS behavior.
- The supported release platform remains `linux/amd64` on a trusted local
  machine or internal lab network.

## Verification

- 847 automated tests passed with 1 skipped during isolated ZAC-79 verification.
- The final `main` workflow passed product tests and the `linux/amd64` image
  build and publication.
- A disposable fresh Docker startup completed successfully, with `lab-app`
  healthy and readiness returning HTTP 200.
